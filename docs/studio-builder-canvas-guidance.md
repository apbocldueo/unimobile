# Studio Builder：画布与引导

2026-09-18，按用户反馈补齐 Builder 内的首次操作引导，并把画布整理成可理解、可恢复的
编辑空间。这个切片处理“进入画布后不知道先做什么”和“节点关系很快变乱”的问题，不改变
AgentGraph 语义、后端接口、保存合同、运行内核或设备边界。

## 用户看到的变化

- 画布左上显示“开始搭建”三步提示：添加能力、连接端口、配置并校验。
- 引导根据当前选择给出下一步提示，但不把步骤标记为已完成，也不伪造运行状态。
- 用户可以隐藏引导；画布右下保留“画布提示”按钮，可随时重新打开。
- 左侧能力库明确提示“点击添加，或拖到画布”，每个能力卡有可读的添加名称。
- 右侧 Inspector 在未选中对象时告诉用户：选中能力配置实现/参数/依赖，选中连线查看
  关系策略，Input/Output 用于确认 Agent 边界。
- 画布右上提供“自动整理”：按普通关系从左到右排列 Input、能力和 Output，反馈关系
  作为回路显示，不参与主流程分层。
- 自动整理只改变 presentation 坐标，作为一次可撤销编辑，并在整理后临时适配视图；再次
  点击已经整理好的图不会产生空的历史记录。
- 画布右下显示图例，区分能力、边界、普通关系和“下一轮反馈”，减少用户靠猜颜色和线型
  理解图的成本。

## 设计边界

引导只使用 React 本地状态和一个版本化 `localStorage` 隐藏偏好。它不写入 Agent 文档、
revision、dirty 状态、compile result 或 server 资源。引导卡本身不拦截画布拖动和连线；
节点仍由 XYFlow 处理，拖拽坐标仍只在松手时进入 Builder store。

自动整理使用当前文档的普通关系计算确定性分层，反馈关系不用于布局。整理结果写入同一份
presentation 节点坐标，并通过 Builder store 的单次历史编辑进入 Undo；它不是运行时执行顺序，
也不会替用户自动修改关系、配置或组件身份。Fit View 只在这次显式命令后临时执行，不持久化
相机位置。

## 验收证据

- 新增引导组件测试，并覆盖隐藏/重新打开、上下文提示和空 Inspector 提示。
- 完整前端回归：**137 个测试文件 / 640 个测试**；`typecheck`、`lint` 和生产构建通过。
- 浏览器实际验证：首次加载显示引导；隐藏后出现“画布提示”；重新打开恢复三步内容；
  引导打开时拖动 Reasoning 节点 5px 仍能产生一次布局修改；点击“自动整理”后节点按主
  流程重排、出现一次可撤销修改，Graph 继续显示通过；撤销后恢复“当前 revision 已保存”。

## 仍然存在的限制

本切片没有自动追踪“用户已完成哪一步”，也没有把引导变成强制向导；研究者可以自由从
任意节点开始。当前自动整理是确定性的普通关系分层，尚未提供对齐辅助线、多选移动、触屏
手势、自动避障或用户自定义布局规则；也没有基于真实运行事件的动态引导。布局只保证编辑
展示更清楚，不代表任意复杂图都能得到最优美观排版。
