# Studio Builder：节点拖拽手感

2026-09-18，按用户反馈修复 AgentGraph 画布的节点拖拽。范围只覆盖画布交互和本地
presentation 状态，不修改 AgentGraph 语义、后端接口、运行内核或设备边界。

## 问题

画布之前为节点移动启用了 20px 网格吸附。用户只想把节点挪开几像素时，节点会先停住，
随后跳到下一个网格点，连线也会跟着出现突跳。这让搭建关系和整理布局都很难控制。

## 修改

- 关闭 XYFlow 的强制网格吸附，让节点位置直接跟随指针；背景仍保留点阵作为视觉参考。
- 拖动开始时将画布切换为 `grabbing` 反馈，普通节点和边界节点都显示一致的拖拽光标。
- 拖动过程中不写入 Zustand 文档状态；只在 `onNodeDragStop` 写入最终坐标。
- 最终坐标继续走已有 `setNodePosition`，因此一次拖动只产生一个可撤销的 presentation 编辑，
  不会改变语义图或重新定义关系。

## 验收证据

- Builder store 定向测试通过：节点位置修改产生一个 history checkpoint，Undo 恢复原坐标。
- Builder canvas 定向测试通过：画布渲染、边界节点选择、连线模式和画布展开行为保持通过。
- 完整前端回归通过：**135 个测试文件 / 635 个测试**；`typecheck`、`lint` 和生产构建通过。
- 真实浏览器在 1280×720 Studio 页面中将 Reasoning 节点移动 5px；页面显示“布局有未保存
  修改”，Graph 仍保持通过；点击一次“撤销”后恢复“当前 revision 已保存”，撤销按钮变为禁用。

## 涉及层

| 层 | 变更 |
| --- | --- |
| XYFlow 画布 | 去掉 `snapToGrid`，增加拖拽开始/结束回调 |
| Builder 样式 | 节点使用 `grab`/`grabbing` 光标并禁止拖动中的文字选中 |
| 本地状态 | 仍只在拖拽结束时调用已有 `setNodePosition` |
| 后端与运行时 | 无变更 |

## 限制

本次没有做帧率基准测试，也没有在触屏、超大画布、浅色主题或移动端浏览器上验证。拖拽
仍受浏览器指针事件和 XYFlow 本身的节点边界约束；更复杂的自动排版、吸附辅助线和多选
移动需要单独设计。
