# 我的 Agents：个人使用入口

日期：2026-09-28。OpenSpec：`agent-first-personal-entry`。

## 决策与实现

用户明确提出：软件由使用者自行部署，入口应围绕自己的 Agent 和任务，而非管理员工作台。Coding Agent 完成路由、导航、Agent 卡片、会话内任务返回、测试与实际浏览器检查。

入口由「产品首页 → 工作台 → Agent → 设计」调整为「产品首页 → 进入知行 → 我的 Agents → 开始任务 / 编辑 / 运行记录」。导航顺序为我的 Agents、运行记录、评测、设置。旧 `/workspace` 以 replace 跳转 `/agents` 并保留查询参数。

保存过版本的 Agent 提供开始任务入口；这不等于已经通过运行准备。运行页继续负责模型、设备、图校验和提交前检查。没有保存版本时不显示开始任务入口。列表按更新时间排序，不声称它是最近使用或任务状态。

首次使用强调从示例创建第一个 Agent；空白创建与 Schema 3 JSON 导入仍可用。原有创建并准备试跑、创建并进入设计流程保留。

`features/recent-run-return` 只读取当前 QueryClient 已知的非终态 Run 身份，再通过既有 Run 查询重新确认状态。请求失败显示检查失败，不把缓存状态说成当前正在运行。查询每五秒刷新，终态停止轮询；链接使用精确 Agent/Run 身份。

## 验证与复现

```sh
cd studio
npm test
npm run lint
npm run build -- --outDir /tmp/zhixing-personal-entry-dist
```

本轮全量 144 个测试文件、673 个测试通过；lint 与生产构建通过。构建仍有 Studio bundle 超过 700 kB 的体积提示。自动化覆盖显式卡片入口、未保存版本、搜索、同名区分、创建回归、缓存状态重查、查询失败和无已知任务时不发请求。

实际浏览器连接本地后端验证：我的 Agents 显示已有四个 Agent；开始任务到运行准备页，尚未提交任务；`/workspace?from=legacy` 转到 `/agents?from=legacy`；新建选择与示例创建表单可显示。未创建额外 Agent，也未调用模型或运行设备任务。

手动验收：从首页点击进入知行；选择一个 Agent 的开始任务，预期先看到运行前确认和任务输入。返回列表点击编辑或运行记录，应分别进入该 Agent 的设计和历史。首次使用空状态由自动化 fixture 验证，不清空用户数据来制造空状态。

## 边界

任务返回只覆盖当前页面会话内查询过的 Run。刷新、离开 Studio 查询 Provider 或重新打开应用后，不保证恢复入口；用户仍可通过精确任务链接返回。完整持久活动任务目录需要独立后端资源，不能以浏览器缓存冒充。没有更改 AgentGraph、BenchmarkTask、模型或设备执行语义，也没有新增执行成功证据。
