## 首轮结果（历史）

- 右侧将配置和检查分开。选择节点自动打开配置；新的失败检查打开检查视图。顶部状态可以直接打开检查，不必再次编译。
- 切换视图采用隐藏而非卸载配置内容。未完成的 JSON、原始编辑状态、撤销历史仍由原有 owner 持有；面板导航不写入 AgentGraph。
- 能力卡片增加 Catalog 提供的实现名称、多候选摘要、实现不可用及已有诊断计数。不读取或展示参数值、凭证；没有诊断不代表已验证成功。
- 配置面板增加关闭按钮，减少嵌套底色。诊断导航与说明改为中文，仍明确不支持精确字段定位的情况。
- 已有能力的流程在没有显式偏好时默认收起新手提示。空白流程保留引导，用户主动选择的显示偏好仍优先。
- 显示全图为顶部面板按钮预留空间；只调整镜头，不自动重排或保存节点位置。

## 手动验证

按现有方式启动项目后，进入任一 Agent 的“设计”页面：

1. 查看节点用途和所选实现，选择节点，预期右侧打开“配置”。
2. 点击顶部检查状态，预期打开“检查”，配置表单不会与诊断挤在同一滚动区域。
3. 在高级 JSON 写入未完成的 `{`，切换到检查再切回，预期内容仍在；恢复原文后继续保存。
4. 点击“显示全图”，预期顶部控件不会盖住最高节点标题。该操作不标记文档修改。
5. 已有旧布局过密时，可显式使用“自动整理”，确认后保存；用户原布局不会被静默重置。

可复现检查：`npm --prefix studio test`、`npm --prefix studio run lint`、`npm --prefix studio run build`。

## 限制

本次没有增加上下文插入、输入来源选择器、关系聚合或节点单步运行。旧布局和大图仍可能需要用户整理、缩放；不宣称卡顿已解决。配置区尚有合同定义的英文参数，后续阶段处理表单语义。构建仍有超过 700 kB 的应用 chunk 提示。
