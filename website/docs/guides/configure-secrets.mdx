# Configure model secrets

## Goal

Bind local values to an AgentGraph's `SecretRef`s without putting API keys into
YAML, canonical hashes, reports, trajectories, or Git.

## Before you begin

The built-in Android Agent uses the secret identities `api_key` and `base_url`.
Inspect `examples/graphs/builtin_android_agent.yaml`: its model dependency
contains `{secret_ref: api_key}` and `{secret_ref: base_url}`, not literal
credentials. Install the optional model dependency first:

```bash
python -m pip install -e ".[openai,dev]"
```

## Create a local mapping

Create `secrets.local.yaml` in the repository root:

```yaml
api_key: "replace-with-your-runtime-key"
base_url: "https://your-openai-compatible-endpoint/v1"
```

`secrets.local.yaml` is ignored by this repository. Do not put real values in
an AgentGraph YAML, examples, issue reports, or committed files.

## Bind secrets at run time

Pass the mapping only to the run that needs it:

```bash
zhixing run \
  --agent examples/graphs/builtin_android_agent.yaml \
  --instruction "Open the camera and take one photo, then finish." \
  --serial emulator-5554 \
  --secrets secrets.local.yaml \
  --artifact-root temp/runs \
  --json
```

Replace the serial with your exact ADB target. The CLI reads a string-keyed YAML
mapping and resolves it only while binding runtime dependencies.

## Verify safely

Successful JSON output contains the canonical hash, run ID, status, and an
artifact manifest path. It must not reveal the key value. A missing or malformed
mapping is a configuration failure before normal Agent execution; correct the
local file rather than editing secrets into the graph.

## Scope

A secret reference is an identity boundary, not a vault or third-party secret
manager. Protect the local file using your normal operating-system and CI secret
controls.
