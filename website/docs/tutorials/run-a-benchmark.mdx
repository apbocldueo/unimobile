# Inspect your first benchmark

## What you will achieve

Validate a complete Benchmark Package without connecting a device or executing
an Agent. This is the safe first step before binding a candidate Agent to a
real Android run.

## Prerequisites

Complete [installation](../getting-started/installation). No device or model
credentials are required for this validation.

## Steps

```bash
zhixing benchmark validate examples/benchmarks/minimal \
  --no-installed \
  --json
```

The checked-in minimal package is deliberately small: it demonstrates the
relationship among a package manifest, task definitions, and an experiment
protocol. Validation checks the definition and its declared closure; it does
not connect ADB, instantiate plugins, execute an Agent, or call a model.

## Understand a real run

When you are ready to run a candidate against a verified device target, the
runtime sequence is:

```text
materialize → reset → setup → evaluator pre-hook
            → AgentGraph Runtime → evaluation → cleanup → reporting
```

## Verify the result

The command returns `"is_success": true` when the package can be compiled into
a BenchmarkPlan and its default ExperimentProtocol is valid. It is definition
evidence only, not execution evidence.

For a real Android run, start from the detailed
[Benchmark running guide](https://github.com/apbocldueo/unimobile/blob/release-v2/docs/benchmark-running.md).
An Agent `success` status is not the same fact as a benchmark `pass`: task
setup, evaluation, or cleanup can change the benchmark outcome.
